## Initial Setup

<Steps>
  <Step title="Install Node.js">
    We recommend using [nvm](https://github.com/nvm-sh/nvm) to manage Node versions:

    ```bash
    # Install nvm
    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash

    # Install and use LTS Node
    nvm install --lts
    nvm use --lts
    ```
  </Step>

  <Step title="Install pnpm">
    ```bash
    npm install -g pnpm
    ```

    <Info>
      The project uses pnpm instead of npm for better performance and disk space efficiency.
    </Info>
  </Step>

  <Step title="Fork the repository">
    1. Go to [angular/components](https://github.com/angular/components)
    2. Click the "Fork" button
    3. Clone your fork:

    ```bash
    git clone https://github.com/YOUR_USERNAME/components.git
    cd components
    ```
  </Step>

  <Step title="Set up remotes">
    ```bash
    # Add upstream remote
    git remote add upstream https://github.com/angular/components.git

    # Verify remotes
    git remote -v
    ```

    <Note>
      Use `upstream` for angular/components and `origin` for your fork.
    </Note>
  </Step>

  <Step title="Install dependencies">
    ```bash
    pnpm install
    ```

    This may take a few minutes on first run.
  </Step>
</Steps>

## Windows Setup

<Warning>
  Windows users should use Windows Subsystem for Linux (WSL).
</Warning>

<Steps>
  <Step title="Install WSL">
    Run as Administrator in PowerShell:

    ```powershell
    wsl --install
    ```
  </Step>

  <Step title="Restart your machine">
    After installation, restart Windows.
  </Step>

  <Step title="Enter WSL">
    ```bash
    wsl
    ```

    You're now in a Linux environment!
  </Step>

  <Step title="Continue with standard setup">
    Follow the installation steps above from within WSL.
  </Step>
</Steps>

<Info>
  For more details, see [Microsoft's WSL documentation](https://learn.microsoft.com/en-us/windows/wsl/install).
</Info>

## Building the Project

### Development Build

```bash
# Build all packages
pnpm build

# Output is in dist/releases/
ls dist/releases/
```

### Development Server

Start the dev app with live reload:

```bash
pnpm dev-app
```

The dev app will open at `http://localhost:4200` and automatically reload on changes.

<Tabs>
  <Tab title="Material Dev App">
    Browse Material components:
    - Navigate to `http://localhost:4200`
    - Select component from menu
    - Test different configurations
  </Tab>

  <Tab title="CDK Dev App">
    Browse CDK components:
    - Navigate to `http://localhost:4200/cdk`
    - Test CDK primitives
  </Tab>
</Tabs>

```bash

```

## Working with Public API

When making changes to public APIs:

### Review API Changes

```bash
# After making changes
pnpm test:api
```

This compares your changes against golden files.

### Approve API Changes

```bash
# Approve changes for a specific target
pnpm approve-api button

# Review the diff
cat goldens/material/button.api.md
```

<Warning>
  Only approve intentional public API changes. These changes may be breaking!
</Warning>

## Getting Build Artifacts

CI stores build artifacts for each PR:

<Steps>
  <Step title="Find the CI run">
    Go to the PR and click "Checks"
  </Step>

  <Step title="Navigate to artifacts">
    1. Click on `upload_release_packages` job
    2. Switch to "Artifacts" tab
  </Step>

  <Step title="Download packages">
    Archives are named: `<package>-pr<number>-<sha>.tgz`

    Example:
    ```json
    {
      "dependencies": {
        "@angular/material": "https://circle-artifacts.com/.../material-pr12345-abc.tgz"
      }
    }
    ```
  </Step>
</Steps>

## Environment Variables

Optional environment variables for the dev app:

### Google Maps API Key

```bash
# In .bashrc or .zshrc
export GOOGLE_MAPS_KEY=<your-api-key>
```

This enables Google Maps examples in the dev app.

## Disabling Git Hooks

If you don't want automatic commit validation:

```bash
# In .bashrc or .zshrc
export HUSKY=0
```

This disables:
- Commit message validation
- Pre-commit formatting

<Note>
  Git hooks help maintain code quality but can be disabled for certain workflows.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Build fails with memory error">
    Increase Node memory:

    ```bash
    export NODE_OPTIONS="--max-old-space-size=8192"
    pnpm build
    ```
  </Accordion>

  <Accordion title="Tests fail randomly">
    Clear caches:

    ```bash
    # Clear node_modules
    rm -rf node_modules
    pnpm install

    # Clear Angular cache
    pnpm ng cache clean
    ```
  </Accordion>

  <Accordion title="Dev app won't start">
    Check port availability:

    ```bash
    # Kill process on port 4200
    lsof -ti:4200 | xargs kill -9

    # Or use different port
    pnpm dev-app -- --port 4201
    ```
  </Accordion>

  <Accordion title="Git hooks not running">
    Reinstall hooks:

    ```bash
    pnpm husky install
    ```
  </Accordion>

  <Accordion title="WSL performance issues">
    Clone repo inside WSL filesystem (not /mnt/c):

    ```bash
    # Good
    cd ~
    git clone ...

    # Bad (slow)
    cd /mnt/c/Users/...
    git clone ...
    ```
  </Accordion>
</AccordionGroup>
